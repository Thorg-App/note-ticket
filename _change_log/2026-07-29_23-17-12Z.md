Strangler-fig step T2 of the bash-to-TS port (plan: `docs-internal/migration-to-ts-high-level.md`). `src/core/` is the data-model layer with **zero CLI knowledge** — no argv, no output formatting, no console.

- `frontmatter.ts` — key-order-preserving frontmatter block + `TicketDocument` with byte-exact round trip (line-based YAML subset; WHY-NOT js-yaml: real parsers differ on edge cases and would silently change the on-disk contract the BDD suite pins)
- `ticket.ts` — `Ticket` entity, immutable `withField`/`withoutField`, `toJsonRecord()` (the `query` payload)
- `ticket-store.ts` — `TicketsDirectory.resolve()`; `collectFiles()` as the single source of truth for "what is a ticket file" (byte-wise `LC_ALL=C` order via Buffer compare); `save()` = write-scratch + rename, parity with bash `_sed_i`
- `id.ts`, `slug.ts`, `dep-graph.ts` — ID generate/resolve, filename slugs, ready/blocked + cycles + dep-tree layout

Parity with `./ticket` was verified **empirically** by a bash-vs-TS differential harness over generated graphs (it caught a dep-tree subtree-depth ordering bug), not by reading alone. 10 divergences are documented; the notable one is `dep cycle`, where bash reports non-cycles and misses real ones and the TS version is deliberately correct.

Testing: `make unit-test` (= `npm test`) runs `node:test` sources from `test/*.test.ts` transpiled by esbuild into `dist-test/` — no test framework dependency added.

No behavior change for users yet: the dispatcher still routes every command except `help` to bash.

T6, the final strangler-fig step. `TS_COMMANDS` is gone because there is nothing left to delegate: every command was already TS-served, so the cutover deleted the dispatcher, every `cmd_*` body and the awk bulk-listing logic. What remains at the repo root is a launcher holding ZERO ticket logic — it resolves its own directory through symlinks (`tk` on PATH is typically a symlink into a checkout), rebuilds the bundle when it is missing or older than any file under `src/`, and execs node preserving `TICKET_INVOKED_AS`. Everything it prints goes to stderr, so `tk query | jq` stays byte-clean on the invocation that builds.

## Distribution (owner decision, 2026-07-30)
Build from source; no prebuilt bundle committed to the repo or attached to a release. The release flow stays "tag it".

**But build-on-FIRST-RUN, as the ticket specified it, is non-functional for packaged installs** — a package prefix is root-owned, so esbuild dies with `mkdir dist: permission denied` and `tk` is broken on arrival. Proved on a `chmod -R a-w` prefix rather than reasoned about. Both packages now build in their own build phase and touch the installed bundle last so the launcher never judges it stale. Owner acked the deviation. A git checkout still builds on demand.

## The parity harness is gone, and its whitelist survived
All 19 declared bash-vs-TS divergences were audited into BDD/unit pins BEFORE deletion, then moved verbatim (plus a new #20) into `docs-internal/migration-to-ts-high-level.md` with numbering preserved — ~14 code comments cite entries BY NUMBER, so never renumber, only append.

Two claimed pins turned out to be fictional and were caught by mutation-testing during review: #7's `query | head -1` half was backed by an assertion that a constant equals 141 (a test that cannot fail), and #13's non-array scalar `deps:` sub-case was marked covered by nothing at all.

## Silent-failure bugs found in packaging
- `while read -r entry; do … done < manifest` drops the final line without a trailing newline — and the final line is `src`. Both bash consumers had it, the Python one did not. A package would have shipped with no sources, a `tk` dead at runtime, and `make test` green.
- `publish-homebrew.sh` would render a formula containing a bare `libexec.install` — installing nothing — if the manifest were unreadable, because the failed redirect did not fail the function.

Both are the same shape as the pre-existing `bin.install \"ticket\"` formula bug, which shipped unnoticed because nothing in the repo ever exercised the packaged layout. `make package-smoke` now replays the install into a read-only scratch prefix and drives `tk` through the symlink; it is mutation-proven to catch that original breakage.

## Behavior changes (both owner-approved)
- `tk <unknown-command>` reports `Unknown command: <name>` plus help, instead of resolving a tickets directory it will never read and complaining that it does not exist.
- A symlinked `tk` now works: the launcher resolves symlinks to the script FILE. The old shim resolved only the containing directory, so it looked for `~/.local/bin/dist/ticket.mjs`. This is what makes symlink installs viable.

Ticket nid_2ziai8ka9l0yak2lxnwlu9lk2_e, delivered in three reviewed phases: 6a5a349 (create + status family + shared plumbing), 10a1450 (dep write form, undep, link, unlink; dep flipped whole), 712c151 (add-note, edit, shim).

## Why the bash bodies are still there
`make parity` builds its reference by copying `./ticket` with the delegation lists emptied. Deleting the now-unreachable `cmd_*` bodies would turn every parity check into TS-vs-TS, so they stay until T6 along with `scripts/parity/`. Same reason the `TS_DEP_SUBCOMMANDS` assignment survives: `harness.py` requires it.

## The gap that mattered
The parity harness materialised its fixtures in Python and so exercised NO write command — the entire ticket was being built against BDD pins alone. `scripts/parity/check_write.py` is now a fourth `make parity` row: 136 cases diffing transcript, every byte under `_tickets/`, and whether each entry is still a symlink, with ids and timestamps neutralised.

## Bugs found by review, not by the gates
- add-note rewrote via write-temp-then-rename, which REPLACES a symlinked ticket with a regular file; bash appended with `>>`. Fixed with `TicketStore.appendTo`.
- Two `$EDITOR` seams (splitting on whitespace, wrong path to the child) survived unit + BDD + parity. Pinned by tests driving the real `spawnSync`.
- Several bash bugs fixed and declared: substring rather than whole-element id removal corrupting neighbours, a missing `deps:`/`links:` field failing silently, body lines being rewritten as frontmatter.

## Method note
An inverted (`diverges=True`) parity case only asserts the two sides DIFFER — it can never pin what TS does. Every divergence #10-#19 also carries a positive unit or BDD pin. Independent mutation testing by reviewers found escaping mutations in all three phases; implementer-reported mutation tables were wrong twice (one masked its exit code through `| tail`, one mutated the wrong function).
